# 설계 결정 로그

2026-11-14 ~ 11-16 Claude와의 작업 세션에서 나온 결정과 근거를 정리한 것이다. **대화 원문이 아니라 정리본**이다. 최신 설계 내용은 [`spec-v0.4.md`](spec-v0.4.md)가 기준이다 (v0.3은 이력으로 남겨 둔다).

## 목표

미제연 11월 미니프로젝트(RC카) PCB 특강에서 쓸 **모델 PCB**를 설계한다. 산출물은 (A) 정답 예시 자료(사양서 · 넷리스트 · BOM)와 (B) KiCad 파일이다. A의 사양서는 v0.4까지 썼고 B는 시작하지 않았다.

## 확정된 결정

| # | 결정 | 근거 |
|---|---|---|
| 1 | 쉴드형은 쓰지 않고 **통합형**(점퍼선 · Arduino · L298N 모듈 없이 한 장)으로 한다 | 쉴드는 Mega 핀 배치에 묶이고, 목표가 "컴팩트"다 |
| 2 | MCU는 **ATmega328P(TQFP-32)** 로 Mega를 대체한다 | 차량 펌웨어가 328P에 들어가는지 avr-gcc로 확인 (플래시 34%, RAM 25%) |

| 4 | nRF24L01+ PA/LNA와 VL53L0X는 **PCB 밖**(커넥터 + 케이블) | 안테나 위치 문제, 거리센서는 앞쪽에 달아야 함 |

| 7 | 설계 기준은 **모터 1개 stall 5.5A**(최악 가정) | 사용자 지시. 비슷한 모터의 stall 전류 중 최악값으로 고정 (19번 참고) |
| 8 | 보호는 **소자(저항 등)와 회로 위주**, 펌웨어 보호는 제외 | 사용자 지시 |
| 9 | 12V 처짐으로 MCU가 리셋될 위험은 **수용** | VL53L0X가 30cm에서 전진을 막는다는 사용자 판단 (후진 · 측면은 못 막음) |

| 12 | 조종기 보드는 확장 과제, 실습은 4단계(MCU 코어 → 전원 → 구동 → 커넥터 · 배선 · DRC) | 이론 ①~④와 대응 |

## 핵심 설명: stall 전류

- 돌고 있는 모터는 **역기전력**이 전원 전압을 일부 상쇄해 전류가 작다. 바퀴가 막히면 역기전력이 사라져 전류가 I = V / R로 커진다 (12V / 2.2Ω ≈ 5.5A).
- 브레드보드 차량에서 문제가 없었던 이유: 같은 L298N 칩과 같은 한계를 쓰고, 모터 전류는 모듈 자체 단자와 패턴만 지나가며, stall이 드물고, L298의 포화전압이 전류를 스스로 깎기 때문이다.
- PCB에서 달라지는 점: 같은 칩이지만 **선폭 · 커넥터 · 다이오드 · 퓨즈 · 방열**을 이제 설계자가 정한다.
- 보호 대응: 퓨즈는 단락 · 배선 화재용(stall에서는 안 끊김), 전류 감지 저항 + NPN이 피크를 제한, 직렬 제한 저항은 발열이 커서 채택하지 않음. 요지는 "저항을 달면 나아진다"가 아니라 "저항으로 전류를 읽고 끊는다"이다.

## 정정 이력 (초기 설명 중 틀렸던 것)

| 틀렸던 내용 | 바로잡은 내용 |
|---|---|
| MAX_PWM이 stall 보호가 된다 | 평균 전압을 약 78%로 낮출 뿐이라 stall 전류는 약 4.3A(5.5A 기준)로 여전히 크다 |
| 5.5A > 2A는 PCB만의 문제 | 기존 모듈에도 같은 L298N이 있다. 달라지는 건 칩 바깥 경로를 누가 설계하느냐다 |
| 퓨즈로 stall을 막는다 | 4A 퓨즈는 약 3A stall에서 안 끊기고, 2A 퓨즈는 정상 구동에서 끊긴다. 퓨즈는 단락용이다 |
| 직렬 쇼트키 3A로 역접속 보호 | 5A 기준에서 용량 부족 + 발열 → P-MOSFET으로 변경 |
| L298의 13 / 50mA가 5V 로직 전류 | 그 값은 12V(VS) 쪽 IS다. 5V 쪽 ISS는 24 / 36mA |
| 모터 판매 페이지에 "13단", "AI 요약" 언급 | 확인하지 못한 내용이었다. 실제 표기는 12V · 200RPM · "지속적 전류 100mA"뿐 |
| 코드 "수정 6곳" | 실제 변경 5줄 |
| 시뮬레이션 초기 버전 | 스위치 모델 오류로 비현실적 스파이크(최대 12.8A). 인에이블 지연(3µs)과 싱크 스위치를 넣어 고침 |

## 특강 덱 개편 (2026-11-15)

기존 446장 덱을 통합 보드 기준으로 고쳐 486장으로 만들었다. 슬라이드 목차는 [`deck-outline.md`](deck-outline.md).

- **새로 추가**: 설계 목표 4가지, 같은 RC카 다른 PCB, 모듈 유지 vs 통합 비교, stall 전류 3단계(개념 → 기존 카가 괜찮았던 이유 → 소자별 보호 역할), 실습 4단계 ↔ 이론 연결
- **고친 것**: 전원 트리(5단계), 보호 다이오드 8개, 5V 부하, LDO 발열, 역접속 보호 비교, 328P 핀맵과 코드 변경 5줄, L298N 칩 핀 표, 커넥터 표, 선폭(5.5A 반영), 실습 3~7단계(MCU 코어 · 전원부 · 구동부 · 통신 · 센서 · 조종기), 정리 표
- **뺀 것**: 기존의 "외부 모듈 vs IC 직접 실장(기존 R5)" 심화 비교 (앞쪽 모듈 유지 vs 통합 비교로 대체)
- **확인한 것**: LibreOffice 렌더로 표 넘침 · 제목 줄바꿈을 점검해 고침. 렌더에서 PowerPoint와 글꼴 폭이 다를 수 있다.
- **아직 못 한 것**: 스크린샷 자리표시(실습 슬라이드)는 비어 있고, 메뉴 경로는 실제 EasyEDA 화면 확인 전이다.

정정: v0.3의 "Enable 주파수 판본에 따라 1kHz급 기재" 메모는 데이터시트 사본에서 확인되지 않아 뺐다.

**이번에도 못 닫은 것**: 전류 제한 회로 실물 검증, nRF MISO 하이임피던스, 핀 번호 대 EasyEDA 심볼 대조 (강사가 EasyEDA를 직접 돌릴 때 확인 — [`handson-checklist.md`](handson-checklist.md)).

## 설계 점검 추가 반영 (2026-11-17)

"PCB 설계 시 빠뜨리기 쉬운 것"을 이 보드에 대 보고, 사양서와 덱에 없던 것을 찾아 반영했다 (사용자 지시). 20번(보드 크기)도 이 점검에서 나왔다. 반영 위치는 [`spec-v0.4.md`](spec-v0.4.md) 맨 앞 "11-17 추가 반영" 표.

| # | 결정 / 결과 | 근거 |
|---|---|---|
| 21 | **L298N 입력 6개(IN1~IN4 · ENA · ENB)에 10kΩ 풀다운을 추가한다.** ENA · ENB는 Rg(1kΩ) 뒤, Enable 핀 쪽 | 328P 핀은 리셋 · 부트로더 · ISP 중 고임피던스이고, 사양서 원칙 1에 따라 업로드 때도 12V가 켜져 있다. 입력이 떠서 HIGH로 읽히면 켜는 순간이나 업로드 중에 모터가 움직일 수 있다. 덱에는 플로팅 → 풀다운 이론이 있는데 보드에는 없었다. 10kΩ 0603(C25804)이라 수량만 6 늘고(합계 7), 5V 부하 증가는 3mA 이하. ⚠ L298 부유 입력의 실제 읽힘은 데이터시트로 확인하지 못했다. 풀다운은 확인 결과와 관계없이 안전한 쪽이라 유지한다 |
| 22 | **큰 전류 경로 레이아웃 규칙 2개를 사양서 10장에 추가한다.** (a) 5A 경로의 비아는 한 층 폴리곤으로 끝내거나 병렬 5~6개 이상 (b) 큰 전류 GND 패드는 thermal relief를 풀어 직결 | (a) 비아 1개는 약 1A 안팎이라 하나만 놓으면 3.2mm 선폭이 무효가 되는 병목이 된다. (b) 패드가 가는 스포크 몇 줄로만 면에 붙으면 면을 깔아도 전류 통로는 그 몇 줄이다. 둘 다 부품 변경 없이 규칙만 추가. ⚠ 비아 약 1A는 관례치, EasyEDA thermal 옵션 이름은 미확인. 설계만 하는 이번에는 직결로 잃는 것이 없다 (실제 제작은 납땜이 어려워짐) |
| 23 | **전류 제한 회로(Rs + NPN)는 필수 실습에 넣는다.** 덱 · 사양서는 그대로 둔다 | 사용자 결정 (11-17). 이전에 내가 필수에서 빼길 권했으나 사용자가 넣기로 했다. 위험은 그대로다: 간이 시뮬레이션만 했고 실물 검증이 없다. 대응은 강의에서 "시뮬레이션만 거친 설계 안, 실물 검증 전"이라고 말로 밝히는 것 (덱의 ⚠ 표시 유지). 정답 보드와 학생 보드가 다를 때 "틀렸다"가 아니라 "검증 전 회로"로 다룬다 |
| 24 | **라우팅은 EasyEDA 자동 라우터로 진행한다.** 덱 실습 14(442~446)를 자동 라우팅 절차로 바꿨다. 12V · 모터 선폭 규칙은 실습 13에서 먼저 넣고, GND는 라우팅에서 빼고 실습 15에서 구리 면으로 채운다 | 사용자 결정 (11-17). 위험 두 가지: (a) 폭 규칙을 안 넣으면 5.5A 선이 기본 폭으로 깔리고 DRC도 폭 부족을 못 잡는다. (b) 한 Net에는 선폭을 하나만 줄 수 있어 ⚠ (포럼 글 기준, 현재 버전 미확인) 12V Net에 붙은 작은 패드와 굵은 선이 충돌할 수 있다. 대응: 실행 후 확인 3가지(미배선 0 · 12V/모터 실제 선폭 · 전원 경로 비아 수)를 덱에 넣고, 안 맞는 Net은 자동에서 빼고 직접 잇거나 구리 영역으로 처리한다. 자동 라우터는 배치 품질과 전류 귀환 경로를 모르므로 뒷면 신호선이 GND 면을 자를 수 있다 ⚠ 추정 (실습 15 확인 항목 추가). 표준판과 Pro는 메뉴 · 엔진이 달라 EasyEDA 버전을 정해야 한다 |

**닫은 것 (11-17)**: L298 입력 문턱 HIGH 2.3V · LOW 1.5V를 ST 데이터시트 사본에서 확인했다. 10kΩ 풀다운이면 입력 LOW 전류(최대 약 10µA)로 생기는 전압이 약 0.1V라 LOW 문턱에 충분히 못 미친다. nRF 입력은 사양서 사본상 5V 입력을 허용해(VIH 최대 5.25V) 328P 5V 출력을 레벨 변환 없이 받는다 (사본 기준).

**이번에도 못 닫은 것**: L298 부유 입력 동작 (규정을 찾지 못함), nRF MISO가 CSN HIGH일 때 놓는지 (사양서 사본은 "tri-state option"으로만 적음), 비아 허용 전류, EasyEDA thermal relief 옵션 (실습 15에서 확인), 자동 라우터의 넷별 선폭 · 비아 적용 여부와 EasyEDA 버전(표준판 / Pro) (실습 13 · 14에서 확인).

**덱 수정 (11-17 저녁)**: 486장 그대로, 12장만 바꿨다. 실습 14(442~446)를 자동 라우팅 절차로 교체(설정 확인 → 실행 → 결과 확인 → 전원 경로 비아 확인, 안 맞는 Net은 직접 보강). 실습 13(440)의 빈칸 "5V · 3V3: [ ] mm"를 **0.5mm 제안값(⚠ 확정 아님)**으로 채웠다. 실습 4(402~404)에 AP2112K EN → VIN과 MOSFET 드레인 · 소스 방향을 넣었다. 실습 2(394) 노트에 328PB · 크리스털 CL / 4핀 · Multiwatt 수직 확인, 실습 15(447 노트 · 450)에 자동 배선이 GND 면을 자르는지 확인을 추가했다. 자세한 목록은 [`../slides/README.md`](../slides/README.md).

## 강의자료 최종본과 미결정 항목 확정 (2026-11-18)

강의는 동료가 맡고, 사용자는 PPT 최종본을 가능한 한 빨리 넘기기로 했다 (사용자 지시). 첨부된 CODEPLANT 디자인(167장)을 최종 형식으로 삼았다. 이 덱은 기존 486장 덱을 줄여 다시 배치한 것이라는 해석 (사용자가 다르다고 하면 486장 구조로 되돌릴 수 있다). EasyEDA에서 직접 해야 하는 것 외에는 모두 확정했다.
